# 升级

升级前确认发布说明的数据迁移要求，并安排维护窗口。在候选版或回退版通过验证前暂停外部业务入口，以免恢复快照时遗漏切换期间的写入。脚本先拉取目标镜像，再暂停前后端写入，备份当前数据库和上传卷。候选后端通过就绪检查后，脚本才启动候选前端。

```bash
./scripts/upgrade.sh 1.0.1
./scripts/status.sh
```

若候选应用启动后失败，脚本会停止应用，将备份恢复到新的数据库和上传卷，用原版本启动前后端。恢复验证通过后，`.env` 指向恢复后的数据。升级仍会以非零状态退出，日志会列出备份及恢复目标。原数据库和上传卷保留供排查。后续备份和升级沿用恢复后的数据位置。

若恢复本身失败，脚本保留备份和恢复记录。处理故障后，用同一环境文件和 Compose 项目重跑原命令，脚本会先从原始备份继续回退。验证旧版就绪后，按日志确认恢复完成，再发起新的升级。迁移和恢复期间请预留一份数据库与上传卷副本所需的磁盘空间。

所有脚本都支持相同的 Compose 合约，用于隔离测试或非默认文件：

```bash
COMPOSE_PROJECT_NAME=pms-staging ENV_FILE=.env.staging COMPOSE_FILE=compose.yaml ./scripts/upgrade.sh 1.0.1
```
